# 개발 안내

## 실행과 검증
정적 ES 모듈 프로젝트입니다. 루트에서 `python -m http.server 8767 --bind 127.0.0.1`을 실행합니다.
`node tests/run-all.mjs`는 모든 순수 로직 및 회귀 검사를 실행합니다. 모델 자산이 있는 실제 체크아웃에서 실행합니다.
`?test`는 수동 시간 제어 진단용이며 `G.sim(seconds)`로 시간을 진행합니다. 일반 플레이에서는 사용하지 않습니다.
테스트 저장은 별도 localhost 포트로 분리합니다. 사용자 저장을 테스트용 수치로 덮어쓰지 않습니다.

## 모듈 경계
- `src/data/chapters/`: 챕터 맵, 웨이브 구성, 역할, 장비, 색상. base.js는 기존 1~4장의 호환 ID를 보존합니다.
- `src/data/stages.js`: 해금과 별/보상 규칙. 장 추가 시 index.js 등록부터 시작합니다. 하드도 이 모듈의 통합 조회를 사용하며 서버 해금 검증은 `server/growth.mjs`가 담당합니다.
- `src/data/rulesets.js`: 일반 전투 standard 규칙. 새 하드 1~3장 정의는 `src/data/hard.js`, 실제 적용은 `src/monsters/hard.js`이며 일반과 별도 ID/진행/보상을 사용합니다. 하드 4~10장은 미구현이며 출정/보상 검증에서 거절합니다.
- `src/data/growth.js`, `towers.js`: 순수 강화 수치·가격·분기. `world/growth.js`, `world/towers.js`는 전투 상태와 모델을 연결합니다.
- 타워는 골드 Lv1~5와 전투 XP(600/2400)를 함께 사용합니다. 전문화는 Lv3 및 2400 XP에서 열리고, `world/growth.js`의 머리 위 표시도 같은 `canSpecialize` 판정을 사용합니다.
- `src/core/roster.js`의 `waveBoss`가 보스 생성과 미리보기 규칙을 공유합니다. 챕터 최종 웨이브에는 해당 챕터 보스 한 마리만 추가합니다.
- `src/account/progress.js`: 저장 정규화/보상. `snapshots.js`: 전체 저장 선택 정책. `account.js`: 세션 소유권·CAS·백업·통신.
- `src/monsters/abilities.js`: 역할별 전투 능력. 공통 처리만 재사용하고, 신규 챕터의 몬스터 외형·공격 모션·패턴·연출은 1~4장의 구현 수준을 기준으로 제작합니다.
- `src/ui/`: 화면, 입력, 설명. 수치 규칙을 UI에 중복 정의하지 않습니다.

## 변경 규칙
원본 GitHub와 원본 Supabase는 수정하지 않습니다. 독립 프로젝트 ID는 xgjbwdmviuhwfhsckdrh입니다.
v1 저장은 정규화 전 원본을 백업합니다. 레거시 하드 기록은 활성 진행에서 제외하지만 백업은 보존합니다. 새 하드는 growth wallet의 별도 hard 진행을 사용합니다.
소비 재화·인벤토리를 최대값/합집합으로 자동 병합하지 않습니다. progress.merge는 과거 오프라인 도구 호환용이며 실시간 저장 경로에서는 호출하지 않습니다.
신규 장비 ID를 추가하면 JS 허용 목록과 Supabase hd3d_valid_item을 함께 갱신합니다.
서버 변경은 `supabase/migrations/`에 좁은 SQL로 남깁니다. 기존 보안/RLS 구성을 초기화하지 않습니다.

## 검증 기준
단위 검사 통과 후 일반 브라우저에서 배치→강화→분기→전투→결과→재접속을 확인합니다.
신규 적은 소환·분열·지속 피해·공중 타격을 직접 실행해 확인합니다. 자동 시뮬레이션 통과를 수동 클리어 또는 최종 밸런스 확정으로 표현하지 않습니다.

## 5~10장 제작 상태와 완료 기준
5장은 전용 모델·전투 패턴·장비를 연결하고 여섯 맵을 브라우저에서 검증했습니다. 6~10장은 맵·웨이브·장비 데이터가 연결된 초안입니다. 기존 모델의 색상·수치·기술 조합을 변경한 적을 신규 몬스터 디자인 완료로 취급하지 않습니다.
각 장은 1~4장처럼 일반 몬스터와 보스의 구별되는 외형, 이동·공격 모션, 역할·패턴, 공격 예고·피격·사망 연출을 구체적으로 구현해야 합니다.
장비는 외형·아이콘·이름·성능·세트 효과·드롭 경로·장착 표시를 연결하고, 획득→상자 개봉→장착→저장/재접속까지 검증합니다. 삭제한 고유템은 재도입하지 않습니다.
5장부터 순서대로 제작하며 구현된 항목과 실제 플레이 검증한 항목을 분리해 보고합니다. 데이터 등록이나 자동 검사 통과만으로 장 제작 완료를 선언하지 않습니다.

## 5장 구현 위치와 검증 범위
- 데이터: `src/data/chapters/swamp.js`, `chapter5.js`. 8종 적(7종 실루엣, 수문장은 갑충 확대형), 나방 둥지는 별도 출현 가중치.
- 전투: `src/monsters/swamp.js`. 고정 착탄 지점, 0.5초 간격 독 피해, 체력 8% 피해 시 치유 차단, 체력 절반 보스 전환.
- 렌더: `swamp-monsters.js`, `swamp-environment.js`, `swamp-gear.js`. 기존 영웅의 무기 본체·애니메이션은 유지하며 장비 장식을 부착합니다.
- 장비: 8계열 × 5등급 이름과 계열별 SVG 8종. 일반 등급과 숨긴 메카닉의 기존 획득 제한은 유지합니다. 전설 무기 기술은 기존 기술군을 사용합니다.
- `tests/swamp.test.mjs`: 구성, 드롭, 세트 합산, 저장. `tests/browser-swamp.mjs`: 새 8773 포트의 게스트 `?stage=5-6&run=1&test=1&flow=1`에서 `verifySwamp()` 호출. 기존 테스트 전투를 비우는 진단이므로 실제 저장에서는 실행하지 않습니다.
- 검증 기준 장비: 마법사 영구 HP/공격 Lv10, 4장 영웅 장비 +5, 타워 연구 0. 판 안 골드는 정상 수급. UI 조작과 실제 시간 전투, 반복 구간 G.sim 가속 검사를 병행했습니다. 5-5 실패 2회 후 배치·강화 순서를 바꿔 클리어했으며, 전 영웅/장비 조합의 최종 밸런스 확정을 뜻하지 않습니다.

## 특성과 하드 저장
`src/data/skill-tree.js`는 전직 후 Lv15/20/30/40/50의 각 2택1을 지원합니다. 출정 영수증은 선택 빌드를 고정합니다.
하드 정산은 wallet/progress/mail/run을 같은 서버 트랜잭션으로 반영합니다. 이력 우편의 server_applied는 재수령을 금지합니다.
클라이언트는 정산 전 flush부터 서버 재조회까지 일반 저장 변경을 잠급니다. 커밋 결과가 불명확하면 계정별 server_save 표식을 남기며, 확인 전 구매는 성공 처리하지 않습니다.
hardRewardSeq가 다른 옛 로컬 충돌 기록은 서버를 덮어쓸 수 없습니다. 임의 최대값/합집합 병합으로 보호를 해제하지 않습니다.
검사: tests/hard-tree.test.mjs, hard-runtime.test.mjs, hard-settlement.test.mjs, tree-client.test.mjs, tree-projectile.test.mjs, tree-fighter.test.mjs.
시뮬레이션 전투 완주와 서버 정산 통과를 별도로 기록합니다. QA 시계 제어는 로컬 모의 서버에서만 사용하며 운영 최소 경과시간은 변경하지 않습니다.

## 상위 특성·하드 2/3장 후보 검증
일반 장의 적/보상 수치는 변경하지 않습니다. 하드 2장의 고정 직선 예고, 3장의 고정 원형 예고는 이동 또는 스턴으로 대응하며 정예는 기존 적을 교체합니다(웨이브 4/동시 2 상한).
`treeMods`의 일반 배율과 `basicTreeMul`의 조건부 배율을 구분합니다. 조건부 추가 관통은 장비 proc를 재귀 호출하지 않습니다. 실제 이동 판정은 입력이 아닌 좌표 변화로 결정합니다.
검사: hard-chapters23.test.mjs, tree-upper.test.mjs, tree-upper-client.test.mjs, tree-upper-server.test.mjs, tree-upper-combat.test.mjs. 기존 정산/처치/대장간 보호 회귀도 함께 실행합니다.
브라우저 suite는 RAM 계정·주입된 진행/성장 fixture·가속 엔진·시험 서버 시계만 사용합니다. 정상 플레이로 성장/해금한 결과 또는 실 Firestore 성공으로 표시하지 않습니다. 하드 3-3/3-5의 개별 HP/구성 조정과 실패 표본은 외부 검수 아티팩트에 보존합니다.

궁수 정밀 마무리는 발사 시 공통 공격/치명타를 계산한 뒤 각 화살/관통 명중 시 `treeImpactMul`을 적용합니다. 추가 대상에 첫 대상의 HP 조건을 재사용하지 않습니다. `tree-arrow-impact.test.mjs`는 실제 공격·전직·투사체 경로와 비행 중 체력 변화, 방어, 치명타 단일 추첨을 검사합니다.
신규 하드 2/3장의 예고는 높은 지형에도 보이는 고정 범위 overlay이며 판정과 독립입니다. 기존 하드 1장 표시와 판정은 보존합니다.
